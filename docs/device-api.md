# Локальный API очков (порт 8080)

## 1. Общая схема

Очки поднимают Wi-Fi точку доступа и HTTP-сервер на **порту 8080**.
Приложение `com.xiaomi.superhexa` обращается к нему по адресу
`http://<ip-очков>:8080`.

В APK шаблон встречается в двух видах:

```
http://%s:8080
http://{host}:8080
```

Второй вариант используется в отладочных/конфигурируемых сборках.

## 3. Заголовки

| Заголовок | Значение | Источник |
|---|---|---|
| `Authorization` | `HEXA1-HMAC-SHA256 nonce=..., timestamp=..., signature=...` | `interceptor.b` |
| `X-Request-ID` | `App_Android_<ts>_<hash>` | `interceptor.b.c()` |
| `X-Mobile-Id` | идентификатор клиента | `tools.b.c()` |
| `X-App-Version` | `Android:<versionName>` | `interceptor.b.a()` |
| `Accept-Language` | язык системы | `interceptor.b.a()` |
| `Content-Type` | `application/json`, если не задан | `interceptor.b.a()` |

Особенности интерцептора:

- если `Authorization` уже установлен — подпись **не пересчитывается**;
- для хостов, содержащих `fds.api.xiaomi.com`, подпись не добавляется;
- тело запроса читается только если оно JSON/multipart и меньше 1 МБ;
- для `multipart` подпись не строится по телу (используется путь).

## 4. Авторизация: два возможных режима

В коде есть два независимых механизма:

1. **HEXA1** — подпись запроса (см. `hexa1-signing.md`).
2. **SV bind** — `SVBindHandler`, `BindKeysResult`, `HmacSHA256` — ключи,
   полученные при спаривании устройства.

Что используется для локального API — надо проверить на устройстве:
возможны оба варианта или их комбинация.

## 5. Как проверять (безопасно)

`tools/probe.py` делает только `GET`:

```bash
python tools/probe.py --scan
python tools/probe.py 192.168.43.1
```

Порядок:

1. Подключить ПК к Wi-Fi очков.
2. Найти IP (`--scan` или посмотреть шлюз).
3. `GET /v1/setting` с подписью → ожидаем `200` или `401/403`.
4. Контрольный запрос без `Authorization` → если тоже `200`, авторизация не нужна
   (маловероятно), если `401` — подпись обязательна.

### Интерпретация кодов

| Код | Значение |
|---|---|
| 200 | доступ есть, можно читать |
| 401 | нужна авторизация (подпись/токен) |
| 403 | подпись верна, но прав нет (нужен passToken) |
| 404 | путь есть, но не для этой модели/версии |
| таймаут | не тот IP, порт закрыт или очки не подняли сервер |

## 6. Чего НЕ делать

- Не вызывать `POST /v1/ota/uploadOtaFile/` без образа и понимания проверок.
- Не вызывать `/v1/resetting` — это сброс.
- Не менять `/v1/change` до того, как прочитан `/v1/setting`.
- Не пытаться «подобрать» passToken перебором — это не нужно и вредно.

## 7. Что даст доступ к API

| Сценарий | Что можно |
|---|---|
| Подпись проходит с одним `serviceToken` | читать настройки, менять чувствительность ношения |
| Нужен `passToken` | взять токен **своего** аккаунта с телефона |
| Нужны SV bind-ключи | нужен дамп ключей, полученных при спаривании |

Практический путь: сначала выяснить, какой режим реально требуется,
и только потом что-то менять.
